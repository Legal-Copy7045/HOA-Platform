# Running the portal: commands, demo data, backups, health and monitoring

Moved from CLAUDE.md when it was cut to its essentials (D90): the same rules and reference, unchanged, read when a task touches this area. A rule here binds exactly as one in CLAUDE.md, which stays the source of truth (if a task conflicts with either, stop and ask).

- Re-apply runtime DB grants: `python manage.py apply_db_grants`
- Actions fewer than two people can perform: `python manage.py check_coverage`
- First officer (once, on the server): `python manage.py bootstrap_first_officer --name ... --email ... [--also-sysadmin]`
- Seed synthetic data (needs `SEED_DEMO_ALLOWED=true`, and with production settings `DEPLOYMENT_STAGE=poc`): `python manage.py seed_demo [--dataset oak_creek|fresh_start]` (`--list-datasets`; registry in `community/demo/__init__.py`, one module per dataset; `oak_creek`, the default, also runs `seed_demo_operations`; run that alone on a community seeded before Milestone 2; it ends with `community/demo/states/`: records in every state, a step waiting for each role, and test personas whose logins sit on their Person email without a password or authenticator, signed in through a board setup link (D59), never a bypass; tester's guide `docs/demo-test-guide.md`; a new area adds its states there and a line in `community/tests/test_demo_coverage.py`)
- Reseed the POC (D53): Settings → Demo data (sysadmin; only with `SEED_DEMO_ALLOWED` and `DEPLOYMENT_STAGE` poc or local, otherwise 404) requests the `reseed_demo` server task; the agent runs `infra/poc/reseed-demo.sh <dataset>` (backup first, `keep_logins export`/`import` keeps non-demo logins with their MFA and sysadmin role under the same ids, drop and recreate the schema, migrate, seed, with `HostTask.attach_requester` the fixed flag `--attach-requester <task id>` runs `demo_attach_requester` (POC only: board seat and a demo home for the requester), `clean_demo_files`)
- Break-glass (sysadmin, audited): `breakglass_end_ownership`, `breakglass_end_role`, `breakglass_lock_user`, `breakglass_enrollment_code` (only while fewer than two other board members can sign in), `rescan_files`, each with `--actor` and `--reason`
- Web/worker refuse to run as the DB owner, or as a role with SUPERUSER, BYPASSRLS, CREATEROLE or CREATEDB (D87): `python manage.py check_db_role` (run by the entrypoint)
- File store write/read/delete probe: `python manage.py check_storage`
- What the database holds (counts only, no personal data): `python manage.py data_status`
- Backups (POC VM): `sudo bash infra/poc/backup.sh [--install]`; restore drill: `sudo bash infra/poc/restore-drill.sh [--allow-unsigned] [dir]` (own scratch file store; refuses backups without the stamped keyed checksum from `infra/poc/backup_mac.py`, whose key never goes on a command line); shared shell helpers: `infra/poc/lib.sh`; file store export/import: `export_files` / `import_files`; off-site backups to a locked R2 bucket (D31): `sudo bash infra/poc/setup-offsite-backups.sh` (proves the lock with `check_offsite_lock`), drill with `restore-drill.sh --from-offsite`, code in `core/offsite.py`; a passed drill records `backup_heartbeat --kind restore_drill` on the live portal (signed backups only). Backups health (D57): in production no off-site copy, one older than 36 h, or no passed drill in 90 days fails; POC/local say "Not production-ready"
- Host security (POC VM, once, idempotent): `sudo bash infra/poc/harden-host.sh` (automatic security updates, Livepatch when Ubuntu Pro is attached, auditd, nightly AIDE, Falco); alerts reach sysadmins via `python manage.py host_alert --kind ...`; System status shows the services
- Health: `python manage.py health_check [--alert]` (VM timer: `infra/poc/health-timer.sh`); server errors are recorded as signatures (D45, `core/errors.py`, `core.ErrorSignature`: class, route name, our innermost code frame, status, release, per hour; never the path, query, message or user; deliberate 503s labelled with `errors.label_error`), described in plain words by `core/error_words.py` (add a route or exception there when the generic sentence is unclear) with the technical line underneath, in the alert email (top 5) and the System status card (24 h); kept `errors.RETENTION_DAYS`; routine update emails go through `comms.notify.send_update` (honours the weekly digest), legal notices never do
- Monitoring (D74): health checks Background jobs (`core/job_health.py`: Procrastinate's tables, failed in a day / retried over 3 / doing over 45 min / waiting over 20 min, task names only, plain words; clearable), Payment processing (`payments/failure_alerts.py`: mismatches, technical autopay failures, Stripe trouble counted per hour in `stripe_api._note_trouble`, decline bursts; counts only; board My item per unresolved failed autopay, `autopay.board_failure_items`), Bounce mailbox, Database connections (warn over 80%) and Storage growth (`core/growth.py`: daily append-only `GrowthSnapshot`, least-squares days until the disk is full, rule `monitoring.disk_full_warn_days`); every check's start and recovery, alert emails, backups and drills (`backup_heartbeat`), updates (the agent), host alerts and bounce bursts go on the append-only `OpsEvent` incident timeline, merged with error signatures and server tasks (`core/ops_timeline.py`, System status card and `ops_timeline`, sysadmin only, no personal data). New kinds of event: `ops_timeline.record(kind, message)`, operations words only
- Load the lot and owner register (go-live): in the portal, Homes and owners → Import homes and owners (`register_import`, board only `ownership.manage`; CSV or .xlsx up to 2 MB, size limit before buffering via `core.uploads.limit_uploads`, malware scan gate, dry-run check, then Import; file kept privately in `RegisterImport`, removed by the board or after `REGISTER_IMPORT_FILE_DAYS`; D54), or on the server `python manage.py import_register register.csv [--commit]` (CSV or .xlsx). Both use `community/register_import.py`; templates are generated (`register_template`; `docs/examples/register-template.csv` matches the CSV); real files never in the repo
- On a fictional-data POC, attach yourself to a demo lot: `python manage.py demo_make_me_owner --email you@... --lot N`
- Quarterly access review (board only, append-only `accounts.AccessReview`, My items after 90 days): `accounts/access_review.py`; contact-details retention for people who left (rule `retention.former_owner_contact_days`, nightly task, board preview at Admin → Contact retention): `community/retention.py`
- Server resources and scanner figures (D39): the VM agent writes memory, swap and load from /proc into `UpdateStatus.host_resources` each minute (`low_since` when under 10% free); `core.health.resources()` / `_memory` (alerts after 10 minutes low) and `scanner_version()`; scan counts from `documents.services.scan_summary()`. No per-container `docker stats` (cost)
