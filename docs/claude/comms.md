# Email, paper mail, alerts and the installable app

Moved from CLAUDE.md when it was cut to its essentials (D90): the same rules and reference, unchanged, read when a task touches this area. A rule here binds exactly as one in CLAUDE.md, which stays the source of truth (if a task conflicts with either, stop and ask).

- Bounced email (D74, optional feature `bounce_tracking`): `comms/bounces.py` reads a bounce mailbox over IMAP over TLS (stdlib `imaplib`, verified certificates, `BOUNCE_IMAP_*` only in the server's .env via `infra/poc/set-bounce-mailbox.sh`, checked by `manage.py check_bounce_mailbox`), every 20 minutes, pull only; outgoing mail is tagged in `core.email` (signed per-message token in `X-Portal-Ref`, the Message-ID and, with `BOUNCE_RETURN_PATH`, a VERP envelope sender; kind from `with mail_kind(...)` or the `X-Portal-Kind` header: official notices must be sent inside `mail_kind(NOTICE)`); DSNs and common formats parsed safely (size caps, no attachments), addresses hashed at once; append-only `EmailBounce`, `EmailBounceClear`, `BounceFollowUp`; a hard bounce shows on the person page and My profile; a hard-bounced official notice puts "Send a paper copy to <address>" on My items (Paper mail) until a mailing for the home or "Sent another way"
- Bounce tokens bind the recipient (BUG-002 / EXP-001): a report counts only for an address the message went to: one recipient, its hash must match the token's prefix; several, it must be in `OutgoingEmail.address_hashes` recorded at send time (no record, no effect); so a forged bounce can mark at most the forger's own address
- Email relay (0.43.0, owner's choice): `EMAIL_PROVIDER` `smtp` (EMAIL_HOST settings, default) or `smtp2go`: SMTP2Go's HTTP API, all of it in `comms/smtp2go.py` (`POST /v3/email/send`, key in `X-Smtp2go-Api-Key`; `SMTP2GO_REGION` global/us/eu/au picks the only host ever contacted; https, redirects refused, `SMTP2GO_TIMEOUT`; errors as short codes with plain words in `FAILURE_WORDS`; never the key, bodies or addresses in logs). `core.email.RedirectingBackend` wraps it (tags, POC redirect; no VERP sender with SMTP2Go) and records every accepted message as append-only `OutgoingEmail` (token, relay, SMTP2Go's `email_id`, kind, `with mail_about(area, pk)`, recipients' keyed hashes; no address or text); `EmailProviderState` keeps the last send, the last failure code and the activity cursor. Key only via `sudo bash infra/poc/set-smtp2go.sh` (hidden prompt, curl check with the key on stdin, sender, `env_update`, restart web and worker, `manage.py check_smtp2go` in the worker, test email; a failure puts back only its keys); web and worker get the key (web sends while a person waits), nothing else
- Delivery reports (pull only, no webhook, no anonymous page): `comms.tasks.poll_email_activity` every 5 minutes (maintenance queue, `comms/delivery.py`) reads `POST /v3/activity/search` from the cursor minus 15 minutes (at most 6 hours, 20 pages of 500 per read), keeps delivered / hard / soft / spam / unsubscribe, stores each once in append-only `EmailDelivery` (deduplicated: a report read twice changes nothing), trusts only events whose `email_id` the portal recorded for its own SMTP2Go send and whose recipient was one of that message's; bounces, complaints and unsubscribes go into `comms.bounces.record` (kinds `spam`/`unsub` count like a hard bounce: bouncing address on the person page and My profile, a bounced official notice on Paper mail). No bounce mailbox is needed with SMTP2Go; the IMAP mailbox stays an optional fallback for plain SMTP. Health check "Email delivery reports" (hidden with SMTP; fails after an hour of failed reads); System status → Email card (provider, last send, last read, 7-day bounces, counts only); set-up wizard line "Email provider (SMTP2Go)"
- ARC decision email (`arc/notify.py`): every decision, appeal decision or deemed approval queues `comms.tasks.send_arc_decision_email` after commit (retries with backoff, `EMAIL_RETRY`; never twice to one address), as an official notice tagged `arc_decision:<id>`; the ARC request shows "Delivered / Bounced / Pending" per decision to those with `arc.view_all` who are not recused (`arc.notify.delivery_for`). Meeting notices show delivered / bounced / pending counts to `meeting.manage`
- SMTP2Go DNS (generic; the owner adds them at the domain's DNS host, values from SMTP2Go → Sending → Verified Senders): SPF `TXT @ "v=spf1 include:spf.smtp2go.com ~all"` (merged into any existing SPF record, one per domain), DKIM `CNAME s<nnn>._domainkey → dkim.smtp2go.net`, return path `CNAME em<nnn> → return.smtp2go.net` (bounces go to SMTP2Go, which reports them), optionally the link-tracking CNAME; and a DMARC `TXT _dmarc "v=DMARC1; p=none; rua=mailto:dmarc@<your domain>"` to start
- Installable app and alerts (`comms`): `/manifest.webmanifest` and `/sw.js` (signed-in; the worker caches static files only); push via `comms/push.py` + `comms/webpush.py` (RFC 8291/8292 on `cryptography`, no pywebpush; keys from `python manage.py generate_vapid_keys`; posts only to `PUSH_ALLOWED_HOSTS`); urgent texts via `comms/sms.py` (providers `none`/`twilio`, verified opt-in on My profile, Board → Urgent texts). Both are optional features ("push", "sms"), off by default
- Paper mail (D55, Association → Paper mail, `mail.print`: board and manager): `comms/papermail.py` (recipients from `community.services.paper_mail_groups`: owners on the deed without email consent, one letter per home and `postal_address`; append-only `Mailing`, `MailingEvent` (mailed once), `MailPiece`; PDFs made on demand with `core.pdf.render_placed`, never stored; audit counts only), views `comms/papermail_views.py`; meeting page, budget page and My items hook in through `comms.services`. USPS Intelligent Mail barcode: `core/imb.py` (spec vectors in `core/tests/test_imb.py`), serials per Mailer ID under `select_for_update` (`ImbSerial`)
- USPS tracking (D60, optional feature `usps_tracking`, off by default): `comms/usps_iv.py` (stdlib urllib IV-MTR client: https only to the configured *.usps.com hosts for `USPS_IV_ENVIRONMENT` cat|production, redirects refused, paced under 400 requests a minute; BCG login `USPS_IV_USERNAME`/`USPS_IV_PASSWORD` only in the server's .env via `sudo bash infra/poc/set-usps.sh`, the password passed to the worker container only (web gets `USPS_IV_PASSWORD_SET`, D87), checked with `manage.py check_usps_iv` in the worker (sign-in only); tokens in process memory only; tests use `comms/tests/fake_usps.py`), polling and statuses in `comms/usps_tracking.py` (pull only, task every 4 hours on the maintenance queue for pieces marked mailed in the last 30 days and not final; append-only `MailPieceScan` deduped by piece, time and opcode, `MailPieceOutcome` for 403 not-ours and "Address checked"; statuses Mailed / Processed / Sorted for delivery on <date> (918/919) / Delivered / No scans after 5 days / Gave up after 30 days; My items once per letter until checked; health check "USPS tracking"; audit `usps.polled` counts only)
